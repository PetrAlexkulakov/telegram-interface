# Telegram Interface (GREEN-API)

Тестовое задание на должность «Фронтенд разработчик React»: пользовательский
интерфейс для отправки и получения текстовых сообщений в Telegram через сервис
[GREEN-API](https://green-api.com/).

Внешний вид взят за прототип с веб-версии мессенджера: слева список чатов,
справа лента сообщений и поле ввода.

## Запуск

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:5173

Сборка production-версии: `npm run build`, локальный просмотр сборки: `npm run preview`.

## Как пользоваться

1. На экране входа ввести `idInstance` и `apiTokenInstance` из личного кабинета
   GREEN-API. Данные проверяются методом `getStateInstance` и сохраняются в
   `localStorage` — при перезагрузке страницы повторный вход не нужен.
2. В левой панели ввести номер телефона получателя и нажать «Создать чат».
   Номер можно вводить в любом формате (`+7 900 123-45-67`), он приводится к
   `chatId` вида `79001234567@c.us`. Готовый `chatId` тоже принимается.
3. Написать сообщение и отправить (Enter или кнопка «Отправить»).
4. Ответ собеседника появится в чате автоматически.

## Используемые методы GREEN-API

| Задача | Метод | Запрос |
| --- | --- | --- |
| Проверка учётных данных | `getStateInstance` | `GET /waInstance{id}/getStateInstance/{token}` |
| Отправка сообщения | `SendMessage` | `POST /waInstance{id}/sendMessage/{token}` |
| Получение сообщений | `ReceiveNotification` | `GET /waInstance{id}/receiveNotification/{token}` |
| Подтверждение получения | `DeleteNotification` | `DELETE /waInstance{id}/deleteNotification/{token}/{receiptId}` |

Приём работает только при включённых вебхуках инстанса (`incomingWebhook`,
`outgoingAPIMessageWebhook`). Если они выключены, `ReceiveNotification` не вернёт
ни одного сообщения — приложение проверяет настройки при входе и предлагает
включить их одной кнопкой (инстанс при этом перезагружается примерно на минуту).

Входящие сообщения читаются по технологии HTTP API: приложение в бесконечном
цикле опрашивает `ReceiveNotification` (long polling), обрабатывает уведомление
и удаляет его через `DeleteNotification`, иначе оно пришло бы повторно.

Обрабатываются типы вебхуков `incomingMessageReceived`,
`outgoingMessageReceived`, `outgoingAPIMessageReceived` (текст сообщения) и
`outgoingMessageStatus` (статус доставки исходящего сообщения).

Базовый адрес API по умолчанию — `https://api.green-api.com`. Если для инстанса
выдан персональный хост, его можно указать на экране входа по ссылке
«Указать другой адрес API».

## Структура

```
src/
├── api/greenApi.js            — HTTP-клиент GREEN-API и хелперы (chatId, разбор messageData)
├── hooks/useNotifications.js  — цикл опроса ReceiveNotification / DeleteNotification
├── components/
│   ├── LoginScreen.jsx        — ввод idInstance / apiTokenInstance
│   ├── Sidebar.jsx            — список чатов и создание нового чата по номеру

│   └── MessageInput.jsx       — поле ввода
├── App.jsx                    — состояние чатов, отправка, обработка уведомлений
└── styles.css
```

## Ограничения

Согласно заданию поддерживаются только текстовые сообщения: вложения, файлы и
другие типы сообщений в ленте не отображаются. История переписки не
запрашивается с сервера — чат наполняется сообщениями, отправленными и
полученными за текущую сессию.

### Два формата chatId

Отправка выполняется по номеру телефона — `381631775854@c.us`, но вебхуки того же
диалога GREEN-API отдаёт уже с числовым идентификатором Telegram: `804731243` у
личных чатов и отрицательный вроде `-1001681300319` у групп. Если это не
учитывать, после первой же отправки в списке появляются два чата: один с
отправленным сообщением, второй — с именем собеседника.

Приложение связывает их по `idMessage`: chatId, в который отправляли, запоминается
в момент ответа `SendMessage`, а когда возвращается эхо-вебхук с другим chatId,
чаты склеиваются, и дальше переписка живёт под каноническим идентификатором
(`src/chats.js`). Порядок ответа и вебхука значения не имеет — гонка обработана в
обе стороны.

Групповые переписки подписываются названием группы, у входящих сообщений в них
показывается автор.
